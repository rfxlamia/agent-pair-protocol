❯ what do u think about agentpair, btw?                                         
⏺ Solid design, human stays in control loop — pairing/session_open/ratify all
  gated. Hash-match signing good: proves same bytes agreed, not just "yes" nod.

  Rough edges hit today:
  - session_msg type "accept" → invalid_payload. Server rejects that enum val
  despite skill doc listing it as conventional. Had to fake it via type
  "propose" body "accept". Minor doc/impl mismatch.
  - human_approve schema differs from skill doc too — doc says approval_code
  from file, real tool wants via_human: true bool instead. Simpler actually, but
  confusing when docs disagree w/ live schema.

  Core idea strong tho — untrusted relay + e2e crypto + explicit mandate
  boundaries (agent_may vs human_required) good pattern for multi-agent
  negotiation w/o blind trust.
